# TEST_SPEC.md — taskq-api Named Test-Case Catalog (Single Source of Truth)

> **Phase 2 deliverable.** Generated by Agent A (ARCHITECT) following the `derive_test_cases.md` protocol. Test names from P1 `TEST_INVENTORY.yaml` are preserved verbatim. Where an inventory name stands for several distinct behaviors, the inventory name carries one scenario and each further scenario is its own sub-row with its own function (TEST_SPEC shape rule 1). This is the SINGLE SOURCE OF TRUTH for test traceability at Gates 1-4. P3 Agent A implements tests FROM this catalog.

**Project**: taskq-api (repo `taskq-retry`)
**SRS version**: git `b9eef45` (`01-requirements/SRS.md`, 10 FR / 12 NFR + NFR-99)
**SAD version**: git `4d69469` + uncommitted working-tree edits (`02-architecture/SAD.md` Round 1; STRIDE threats T-01..T-17)
**TEST_INVENTORY.yaml version**: git `b9eef45` (100 entries; naming authority)
**Generated**: 2026-10-08
**Active NFR Patterns**: NP-01, NP-02, NP-03, NP-04, NP-06, NP-07, NP-08, NP-09, NP-10, NP-12, NP-13, NP-14, NP-15

Conventions used by every table below:

- `Inputs` use the TRUE value form `key="value"`. Keys named `result_*` in predicates are production outputs and are never declared as Inputs.
- `state_mode` (`shared | isolate_per_case | isolate_per_test`) is declared on every case that touches mutable state (database file, rate bucket, executor counters). `isolate_per_test` requires function-scoped fixtures; `shared` is used only where the case declares a read-only seed or one deliberately shared bucket.
- `subprocess_mode` (`in_process | out_of_process`) and `shared_TASKQ_HOME` (bool) are declared on every case that spawns a process. This project has no `TASKQ_HOME`; its analog is the database location (`TASKQ_DB_URL`), so `shared_TASKQ_HOME="true"` means the parent test and the child process point at the same database file. `out_of_process` cases must propagate `PYTHONPATH` to the child env (pytest `pythonpath` config does not inherit).
- Open spec decisions that a case rests on are named in its `precondition`: `FR-01-deferred` (injection-character blacklist content, SRS NFR-99-1), `FR-07-deferred` (revision that creates `rate_buckets`), `NFR-99-2` (`interrupted` status), `NFR-99-3` (timeout status code), `NFR-99-4` (metrics percentile set), `NFR-99-7` (NFR-01 measurement scope). No assertion is invented for them.
- Sub-assertion predicates never use stdlib or builtin names as their left-hand identifier (`json`, `os`, `sys`, `time`, `subprocess`, `pathlib`, `asyncio`, `typing`, `logging`, `path`, `file`, `id`, `type`, `dict`, `list`, `set`, `tuple`, `str`, `int`, `bool`, `bytes`). Domain names are used instead (`result_content_type`, `result_problem_type`, `result_exception_type`, ...).
- No FR here declares a `**Properties**` table: no FR has an invariant that is both clean Python-expression syntax over declared cases and free of unbound symbols, and an unbound symbol would force a `review_ref` file outside this deliverable. Round-trip and idempotence behavior (FR-07, FR-05) is locked by the example cases and sub-assertions below.
